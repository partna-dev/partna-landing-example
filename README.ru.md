# partna-landing-example

[English](README.md) · Русский

Эталонный лендинг партнёрской программы Partna. Склонируйте, запустите, прочитайте
[AGENTS.md](AGENTS.md) — и собирайте свою страницу, не нарушая правила про деньги.

Это пример, а не продакшен. Данные вымышленные, суммы маленькие, бэкенд —
заглушка.

## Что показано

| Сценарий | Где | Что видно |
|---|---|---|
| Клиент без партнёра | `/` | Цены без скидки |
| Клиент по ссылке партнёра | `/?ref=IRON` | Скидка 10 %, цена пересчитана |
| Сертификат покрывает часть | `/order/p_consult?ref=IRON`, код `CERT5000` | Остаток сертификата и сумма к оплате |
| Просроченный сертификат отклонён | та же страница, код `CERTOLD` | Ошибка, заказа нет |
| Неизвестный код партнёра отклонён | `/?ref=PIRATE` | Скидки нет, бэкенд отклоняет привязку |
| Почему страница не принимает деньги | `/payment` | Граница между лендингом, бэкендом владельца и ядром |
| Что сервер отправит | `/order/<услуга>` после отправки | Два факта в форме контракта моста |

## Живой пример

<https://example.partna.dev> — тот же код с `noindex` и бэкендом только в памяти.
Ничего не сохраняется, каталог и сертификаты сбрасываются при перезапуске.

## Запуск

```bash
npm install
npm run mock    # заглушка бэкенда владельца на :8787
npm run dev     # лендинг на :4321
```

Или через Docker:

```bash
docker compose up --build
```

Приёмочные проверки, без браузера:

```bash
npm run accept
```

Скрипт поднимает заглушку, дважды отправляет заказ IRON с `CERT5000` и сверяет
суммы, идемпотентность, отказ без ключа, неизвестного партнёра и просроченный
сертификат. При расхождении — код возврата 1.

Ключи, аккаунты и сервисы Partna не нужны: цены, партнёры и сертификаты лежат в
[data/catalog.json](data/catalog.json).

`PUBLIC_ROBOTS` управляет индексацией: по умолчанию `index`, `noindex` — для стенда,
который не должен попадать в поиск. Заглушка ограничивает `/api/lead` десятью
запросами в минуту с адреса и держит ответы только в памяти. `CERT_RESET_MINUTES`
возвращает потраченный сертификат через столько минут — на стенде это нужно, чтобы
демо не закончилось; без переменной сертификат остаётся потраченным.

## Структура

```
data/catalog.json          фикстуры в форме контракта чтения
src/lib/price.ts           единственное место, где считается цена со скидкой
src/lib/catalog.ts         фикстуры, коды партнёров, остатки сертификатов
src/layouts/Base.astro     оболочка: head, бренд, подвал
src/pages/index.astro      каталог
scripts/acceptance.mjs     проверки сумм и идемпотентности
src/pages/service/[id].astro
src/pages/order/[id].astro  форма заявки (заглушка бэкенда)
src/pages/payment.astro    где на самом деле двигаются деньги
src/components/PriceTag.vue цена со скидкой и без
src/components/OrderForm.vue заявка, ключ идемпотентности, ответ сервера
mock-backend/server.mjs    заглушка бэкенда владельца
```

Лендинг собран на Astro с Vue-островами: тексты и цены есть в HTML, который
отдаёт сервер, в браузере оживают только цена и форма.

## Правило, из-за которого цены сходятся

Сервер не доверяет числам из браузера, а страница не придумывает свои. Формула
записана в контракте:

```
discountMinor = priceMinor * discountBp // 10000
clientPriceMinor = priceMinor - discountMinor
```

`src/lib/price.ts` реализует ровно её, и заглушка бэкенда повторяет её на сервере.
Если они разойдутся, это будет видно в демо.

## Контракт заявки

`POST /api/lead` — то, что лендинг отправляет бэкенду владельца. В примере его
реализует заглушка, у вас его реализует настоящий бэкенд.

| Поле | Тип | Обязательно | Смысл |
|---|---|---|---|
| `serviceId` | string | да | какая услуга из каталога |
| `name` | string | да | кто спрашивает |
| `contact` | string | да | почта или телефон, он же идентификатор клиента |
| `partner` | string | нет | код партнёра из ссылки |
| `certificate` | string | нет | код сертификата клиента |

Заголовок `Idempotency-Key` обязателен. Тот же ключ возвращает тот же ответ с
`duplicate: true`. Без него бэкенд отвечает `400`.

```bash
curl -sS -X POST http://localhost:8787/api/lead \
  -H 'Content-Type: application/json' -H 'Idempotency-Key: demo-1' \
  -d '{"serviceId":"p_consult","name":"Маша","contact":"masha@example.com","partner":"IRON","certificate":"CERT5000"}'
```

Ответ (денежная часть):

```json
{
  "leadId": "6f1c...",
  "priceMinor": 500000,
  "discountMinor": 50000,
  "clientPriceMinor": 450000,
  "discountBp": 1000,
  "certificateMinor": 300000,
  "certificateLeftMinor": 0,
  "dueMinor": 150000,
  "duplicate": false,
  "facts": []
}
```

Ошибки: `400` без ключа или с битым телом, `422` при неизвестной услуге,
неизвестном коде партнёра, просроченном сертификате, без имени и контакта.

Сертификат списывается один раз: заглушка помнит остаток и отклоняет код, у
которого прошёл `expiresAt`. Настоящий бэкенд делает то же в одной транзакции —
поэтому лендинг не должен резервировать сертификат сам.

## Что значат суммы в фактах

`amount` — сколько клиент заплатил после скидки и сертификата; `retailAmount` —
цена по прайсу; `certificateAmount` — сколько покрыл сертификат. `personalVolume` —
объём для расчёта, `0` значит, что отдельный объём у тенанта не используется.
Разница между `retailAmount` и `amount + certificateAmount` — скидка партнёра.

Имена полей — в контракте:
[fields.md](https://github.com/partna-dev/partna-bridge/blob/main/docs/integrations/fields.md).

## `discount` в фикстурах

`discount.limitBp` — потолок тенанта, выше него не поднимется ни один партнёр.
`discount.currentBp` — процент, который вошедший партнёр видит для себя в
`GET /v1/portal/me`; лендинг, который знает только код, берёт `partners[code]` и
обрезает его потолком.

## Как сделать своим

1. Замените `data/catalog.json` на свои услуги, партнёров и сертификаты, сохранив
   имена полей. Название бренда переезжает вместе с ним.
2. Направьте `PUBLIC_API_BASE` на свой бэкенд и реализуйте там `POST /api/lead`.
3. Замените вызовы заглушки на вызовы моста: сначала `claim`, затем `order`,
   у каждого свой `eventId`, который сервер создаёт один раз и хранит.
